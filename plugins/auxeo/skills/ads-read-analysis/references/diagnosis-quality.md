# Diagnosis Quality

仅在用户要求原因分析、风险判断或动作建议时使用。

## 诊断检查

- 症状：先确认对象、指标、时间窗口、对照窗口和 data health。
- 候选：保留多个合理原因，不把第一个解释当结论。
- 区分：选择能区分候选原因的 evidence，而不是机械查询更多数据。
- 反证：主动寻找会推翻主要原因的信号。
- 层级：判断是单一素材/广告组/campaign，还是账户、App、市场、平台或业务链路问题。
- 时间：配置、素材、状态或回传变化应早于或同时于结果变化。
- 证据：账户事实来自 Ads MCP；指标公式来自 metric binding；方法论来自 Domain Pack；当前政策来自 Web Search。
- 结论：区分“已观察事实”“更可能解释”“尚未排除”“当前无法确认”。
- 动作：给出优先 probe 或建议动作，说明前提、风险和人工确认点。

## 不应发生

- 仅因一个指标越线就给强动作。
- 把空数据当作零或把 stale source 当作当前事实。
- 用 campaign 名称猜 app、状态、预算模式或投放策略。
- 用公开网页覆盖内部账户状态和实际花费。
- 为匹配某个 pack 而忽略新的、证据更强的原因。
- 把每个诊断问题强制走相同工具顺序。
